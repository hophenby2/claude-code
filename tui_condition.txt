当前 TUI 仍失败的原因线索

虽然 REPL mount 了，但没有可见 UI，也没有捕获到 prompt 回复。debug 中新的关键问题是：

[FileIndex] getProjectFiles called, respectGitignore=true
[FileIndex] getFilesUsingGit called
[FileIndex] git ls-files error: The "signal" option has been renamed to "cancelSignal" instead.
[FileIndex] git ls-files returned null, falling back to ripgrep
...
RipgrepTimeoutError: Ripgrep search timed out after 20 seconds.
[FileIndex] cache refresh completed in 52704ms

也就是说，TUI mount 后马上进入文件索引刷新，git ls-files 因 Node API 参数问题失败，然后 fallback 到 ripgrep，而 ripgrep 又超时。这个过程阻塞/拖慢了 TUI 可交互路径。

另外仍有：

Failed to check metrics opt-out status: Auth error: No API key available

但这个发生在退出/telemetry shutdown 附近，不像是主阻塞。

理由：用户要求的是“构建其 TUI 并测试其功能”，最低要求是能观察到初始界面并进行基础交互。虽然现在 REPL 已经 mount，但没有可见 UI 输出，也没有完成基础 prompt → response 流程，所以不能判定 TUI 可用。

---
建议下一步修复方向

下一步应集中处理 TUI mount 后的阻塞项：

1. 修复 git ls-files 的 Node 版本兼容问题

debug 里明确说：

The "signal" option has been renamed to "cancelSignal" instead.

需要找到 git ls-files 调用处，大概率在：

- src/hooks/fileSuggestions.ts
- 或相关 file index / suggestions 代码

把传给 execFile / execFileNoThrowPortable 的 signal 参数改成当前 wrapper 需要的 cancelSignal，或者让 wrapper 同时兼容两者。

2. 避免 TUI 启动时文件索引阻塞首帧

即使 git fallback 正常，TUI 启动时不应该因为 file index / ripgrep 卡住 20~50 秒才可用。可以考虑：

- 在 --bare / CLAUDE_CODE_SIMPLE=1 下跳过 file suggestion index
- 或把 file index 刷新放到首帧之后更晚的 idle 阶段
- 或加短超时并失败静默

3. 增加 TUI smoke 专用模式

为了自动化验证，建议加类似：

CLAUDE_CODE_TUI_TEST=1

或：
--tui-test-mode

内部做：

- 禁用 alt screen
- 禁用 mouse tracking
- 禁用 file index warmup
- 禁用 plugin/LSP startup side effects
- 禁用 stdin /dev/tty override
- 保留真实 REPL render 和 prompt input

这样 TUI 才能稳定被 expect 或 PTY 捕获。
